# Session notes API

All routes use `/api/session-notes`; `/api/v1/session-notes` is the public versioned alias. Requests use the authenticated owner even for administrators. Browser requests cannot supply provenance, an owner, or filesystem paths. JSON success responses are `{ success: true, data }`.

| Method and suffix            | Request                                                                    | Data                                                                           |
| ---------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| GET `/context`               | —                                                                          | `{ ownerKey, instanceKey }`, opaque persistent scope for browser drafts        |
| POST `/open`                 | `{ sessionId }`                                                            | Notebook or durable metadata-only draft; source ownership must be verifiable   |
| GET `/`                      | Optional `q`, `projectId`, `sessionId`, `unfinished=true` query parameters | Canonical notebook entries, newest filesystem modification first               |
| GET `/:id`                   | —                                                                          | Current notebook or retained draft; independent of source session lifetime     |
| PUT `/:id`                   | `{ revision, markdown, title? }`                                           | Saved notebook; an empty first draft stays metadata-only                       |
| GET `/:id/export`            | —                                                                          | Markdown body download, preserving whitespace and line endings                 |
| POST `/:id/reassign`         | `{ revision, projectId }`                                                  | Notebook or draft with its new project assignment                              |
| PATCH `/:id/checklist`       | `{ revision, line, checked }`                                              | Notebook with only the selected source marker changed; lines start at 1        |
| GET `/projects`              | —                                                                          | Owner-private project registry, synchronized with the owner's configured cases |
| PATCH `/projects/:id`        | `{ name }`                                                                 | Renamed project                                                                |
| GET `/recovery`              | —                                                                          | Preserved malformed or unpublished journal artifacts                           |
| POST `/:id/repair`           | `{ revision, markdown }`                                                   | Repaired malformed notebook using retained server provenance                   |
| POST `/:id/resolve-recovery` | `{ revision, projectId, choice: 'external' \| 'staged' }`                  | `null` after choosing a preserved recovery candidate                           |

Explicit sharing routes:

| Method and suffix           | Request                               | Data                                                                                            |
| --------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------- |
| GET `/destinations`         | —                                     | Active sessions with exact authenticated ownership: `{ id, name, mode }[]`                      |
| POST `/:id/send-preview`    | `{ destinationId, text }`             | Immutable `{ token, text, destination }`; validates notebook ownership and eligible destination |
| POST `/:id/send`            | `{ token }`                           | `{ delivery: 'submitted' \| 'failed' \| 'unknown', message? }`                                  |
| POST `/:id/append-response` | `{ revision, sourceSessionId, text }` | Saved notebook with the selected response appended                                              |

Selected text must be nonblank, at most 65,535 characters, and contain no terminal control bytes except tab and line endings. The server does not substitute canonical notebook contents for a preview: explicit selections may include local draft text. Tokens bind the exact text, notebook, owner, and destination, expire after five minutes, and are consumed synchronously before dispatch. Pending tokens are bounded to 256 across owners; expired tokens are pruned when reserving another preview. A consumed, expired, foreign or restart-invalidated token returns 400. This prevents replay of a confirmation within its server instance; it is not a durable exactly-once transport guarantee.

Send dispatch rechecks exact ownership and live session identity, checks remote reachability and worker liveness without wake/resume, then follows ordinary manual-takeover and user-input tracking. Literal bracketed paste preserves multiline text, followed by a separate Enter. A missing or partial transport acknowledgment returns `unknown` without fallback or automatic retry. `submitted` acknowledges the transport, not agent processing. No notes route starts or resumes a session.

Response append independently verifies trusted source ownership and notebook ownership, obtains its ISO timestamp and readable source title/ID reference from the server (Markdown punctuation is escaped), and checks the expected revision inside one owner filesystem transaction. Existing Markdown body bytes remain a prefix of the new body. Concurrent appends with one revision produce one success and one 409; malformed targets produce 422 with preserved bytes. The client retains its selected response and editor drafts and requires explicit review before trying against a newer revision. Appending never sends agent input. An append that would exceed the 1,048,576-character editable Markdown limit returns 400 without changing the notebook.

A notebook contains `metadata`, `markdown`, and a full-byte SHA-256 `revision`. A durable metadata-only draft has an opaque `draft-<SHA-256>` revision derived from its persisted binding, including a monotonic edit stamp. Blank saves, title edits, and reassignment return the current draft revision; clients must use that token for the next write. IDs and trusted session bindings survive reload and failed first saves. List entries contain `id`, `projectId`, `note` when valid, `lastModified` in epoch milliseconds, `unfinishedCount`, `checklist: [{ line, checked, text }]`, and trusted observed `sessionAliases`. Malformed entries retain `raw`, `error`, `repairable`, and any recovery `conflict`.

Notebook mutations check the loaded revision inside one filesystem owner transaction, covering first materialization and binding/project changes across competing service instances. Stale draft or canonical writes return 409 with `{ success: false, errorCode: 'CONFLICT', data: { current } }`; `current` is the current notebook, malformed `{ raw, revision, repairable: true }`, or `null`. Malformed or provenance-mismatched reads/opens return 422 with raw bytes, their revision, and stable `id`/`projectId` identity. Original provenance is checked against retained server records before session association; externally added aliases are never learned from an existing notebook. Body/title edits and valid project moves remain editable. Explicit repair restores retained original provenance, preserving displaced bytes. Invalid input returns 400; unknown or foreign resources return 404. Unexpected disk errors remain server failures. A malformed notebook with no retained provenance cannot be automatically repaired.

`notes:changed` SSE events contain only `{ ownerKey }`. Delivery requires an exact owner match, including for administrators. Filesystem notifications trigger canonical rescans; periodic scans cover missed events. The server closes watchers on shutdown. Search/checklist projections are rebuilt from Markdown files; deleting a search cache cannot delete notebooks.

Native/resume aliases and worktree associations come from the existing trusted unified-session inputs. Multi-user historical opens fail closed when source ownership is unknown. Chosen configured cases are captured at launch, retained in session state, and take precedence over directory inference for new notebooks. Existing assignments, including manual moves, take precedence on later opens.
