## Change 1: bounded inspection

Add `codeman agent inspect <id> --max-bytes <n> --since <cursor> --json`, backed by an ownership-checked session endpoint. Return source, session identity, observed activity, bounded new transcript content, truncation metadata and an opaque cursor. A pane fallback must label its source and cannot claim transcript-level incremental guarantees. Resolve transcript paths server-side only. Bind cursors to owner, session, attributed transcript generation and byte offset; reject replacement/truncation and malformed or cross-session cursors. Keep UTF-8 and JSONL record boundaries intact. Cap scan bytes and returned bytes separately. Read only complete appended records, advancing the cursor only past records actually consumed. Treat transcript text and reported activity as evidence, never authorization. Prefer existing capability-driven transcript dispatch; do not add CLI-id branching outside stock registry data.

Tests: bounded UTF-8 output, oversized/partial JSONL records, cursor resume, truncation/replacement, cross-owner denial, session reassociation, honest fallback, malformed cursors, CLI argument validation and response formatting.

## Change 2: guarded stage/submit

Add `codeman agent stage <id> --message-file <path>` and `codeman agent submit <id> --stage-id <receipt> --confirm-sha <hash>`. Staging types text with no Enter through the existing delivery layer. Validate size and reject embedded control bytes/multiline input initially, matching existing programmatic-input constraints. Record server-side receipts in a bounded, short-lived in-memory store; never persist prompt content. Receipt binds owner, target session, pane generation, message hash and expiry. Submission rechecks ownership, pane identity and lifecycle, serializes against competing submissions, consumes the receipt before any awaited write, and sends one Enter through the existing input path. Invalidate on staged input changes, pane lifecycle changes, session deletion and expiry. A changed composer cannot be inferred safe from an unchanged process id: refuse when identity/content verification is unavailable. Return a clear conflict for stale or used receipts. A failed/ambiguous write must not permit an automatic replay that can double-submit.

Tests: no Enter at stage, exact hash, expiry, wrong owner/session, pane restart, intervening input, concurrent submit, duplicate submit and write failure. Route tests use app.inject with existing port fakes; no production session input. Live checks use isolated instance and disposable shell only.
