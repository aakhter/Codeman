# COD-247: Stable Full-Navbar Tab Hover

## Problem

On desktop, session-tab controls are removed from layout while hidden by setting their width and padding to zero. Hovering
a tab animates the gear, detach, and close controls back to their natural widths. When the navbar is exactly full, expanding
the last tab moves it to the next flex row. The pointer then leaves the moved tab, the controls collapse, and the tab returns
to its original row under the pointer. This repeats as a visible navbar and page flicker.

A focused Chromium reproduction recorded 44 `mouseenter` and 44 `mouseleave` events in one second while the final tab
oscillated between the first and second rows.

## Approved Behavior

- Desktop tabs permanently reserve layout space for the gear, detach, and close controls.
- Hidden controls remain visually unobtrusive and cannot intercept pointer input.
- Hover and keyboard focus reveal controls without changing tab width, padding, row, or navbar height.
- All session controls remain accessible.
- Mobile and tablet tab behavior remains unchanged.

## Design

### Stable desktop control geometry

Update the desktop rules in `src/web/public/styles.css` so each control has an explicit, non-zero inline size and padding in
both hidden and visible states. The hidden state uses opacity and pointer-event visibility only. Hover changes opacity,
color, and existing decorative effects, but never changes layout-affecting dimensions.

Keep the current DOM generated by `src/web/public/app.js`. No JavaScript state or hover event handling is needed.

### Interaction and accessibility

The controls retain their current `tabindex="0"` and accessible labels. Use `:focus-visible` alongside tab hover so a
keyboard-focused control becomes visible. Hidden controls must use `pointer-events: none`; hover or focus restores pointer
events for the intended control surface.

The existing mobile media-query rules continue to decide which controls appear on active and inactive tabs. Desktop base
geometry must not override those mobile display and sizing rules.

## Testing

Add a focused Playwright regression case for a desktop navbar at the wrapping boundary:

1. Render enough representative session tabs to fill one row.
2. Enable the existing desktop auto-wrap class.
3. Hover the final tab on the first row.
4. Assert the tab's top/left position, width, and the navbar height remain stable.
5. Assert the controls become visible.

Run the existing `test/tab-overflow.test.ts` policy tests and `test/mobile/header-buttons.test.ts` browser tests to verify
that auto-wrap decisions and the collapsible mobile/tablet navbar remain intact.

## Scope

This fix changes only session-tab control geometry and focused regression coverage. It does not change tab overflow policy,
the number of rows, session ordering, header utility wrapping, or mobile/tablet navigation behavior.
